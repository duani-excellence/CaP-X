## 结论范围

本轮落实了开放程序入口、版本化公共 Belief、明确的计划返回协议、局部运动提案验证、部分几何诊断与当前深度补证、分层动作状态及恢复上下文。不是新增一套 Runner。原生物理评分、Sandbox、父进程许可及释放阈值不变。

尚不能称为完整通用机器人 Harness：已有成熟 Skill 的可达性、碰撞/抓持与精细控制仍制约物理成功；局部运动检查是保守采样原型，不是完整连续碰撞规划。不能用软件测试或冻结帧通过代替四物体物理成功。

## 实现与边界

- `contract_models.py` / `causal_plan.py`：open 模式不再要求字面量 Skill 序列。静态分析只登记调用点及条件性，不冒充完整 Python 数据流分析。真实调用仍由父进程登记和验证。
- `open_recovery.py`：初始/恢复共用一份完整文档；参数化 `plan_skill/run_plan`、观测、历史/Belief 查询与 `plan_motion`。明确成功计划状态 `READY_FOR_LIVE_VERIFICATION`。第一轮真实模型误用 `ok` 的失败已保留。
- `belief_state.py`：索引现有 Scene/Skill 的几何、抓持注册、模型形状、部分容器、机器人/F/T、质量与来源版本。与三值条件分开；无数值依据的误差、身份置信度保持未知。旧状态不自动成为许可；模型形状明确标识为推断。原点云/RGB-D 由归档引用。
- `open_motion.py`：计算横移/旋转局部提案，核对起始编码器/TCP/附件、证据与资源；工具/附件及实际 IK 输出路径使用公开 RGB-D 和机器人模型抽样检查。未知空间拒绝，原 F/T 保护与收敛检查保留。尚无真实成功横移恢复案例；采样视觉网格及有限可见性不等于完整自碰撞/连续碰撞证明。
- `persistent_harness.py` / `agent_events.py`：API_RETURNED、OBSERVED、DONE/FAILED 分离。goto 的 DONE 绑定真实调用与新鲜 TCP 收敛核验。夹爪关闭只观察编码器，不能因此宣称抓持。原事件历史保留。
- `ProgressTracker`：记录条件、几何覆盖/残差、对应目标误差及有界搜索的最好进展；新 ID、同样的缓存或无目的微动不刷新进展。重复无信息策略仍有界退出。
- `native_vision.py` / `region_geometry.py`：保留部分几何、axis/缺失壁面；当前深度重拟合如上。
- `vision_skills.py`：放置候选增加目标距离、边界余量、运动代价，释放后记录质量和稳定性；没有增加额外原生成功条件。当前还不是完整多目标规划，邻物间距、后续兼容性、完整路径风险没有统一可靠评分；不伪造这些值。
- `sandbox.py`：只修复异常退出时 API 尝试计数丢失；没有修改隔离、允许列表、调用上限或超时。

## 开放能力尚存限制

1. `acquire/deposit` 已可参数化，但并未把每个内部阶段都开放成可独立重组的执行原语。当前能力库不能保证任意安全暂放、重抓或主动调整已完成目标。
2. 已完成动作 ID 不可重放；物理目标被新证据撤销后可产生新计划。对“仍满足原生目标但质量不佳”的重新抓取尚无合格通用技能，不能声明已实现。
3. 信息动作候选来自已有壁面射线与工具遮挡假设，需经过同一运动准入；并未证明其在真实 Cereal 场景提供新信息。重复静态观测不算进展。
4. Belief 目前是可检索、带来源与不确定性的公共估计索引，仍不是完整概率世界模型；动作许可继续由既有具体验证器签发，未把未知世界空间补成自由空间。
5. Checkpoint 保存任务状态与审计，不回滚物理世界、不自动恢复崩溃后的仿真进程。LLM 请求期间 MuJoCo 暂停步进，不代表真机长期安全持物。
6. 共同能力提供给 G0/G1；本轮先验收开放 G0，没有新 G1 优势结论。

### 真实恢复案例与未完成原因

1. Milk：新模型代码通过参数化 acquire/deposit 实际抓取、搬运。释放前几何区间未通过，一次约 3.8 mm 修正没有改善，触发 `Local alignment made no measurable progress`。随后确定性恢复完成放置；因此不能把 Milk 的全部恢复归给 LLM。
2. Bread：后续 approach 在闭爪前触发 F/T 保护。公开传感器记录模拟时间 24.7 s、夹爪约 79.9 mm，滤波力向量约 `[-119.3,72.8,132.8] N`；没有放宽保护。力曲线见产物 `force-stop.png`。
3. 最终协议版本的**新 DeepSeek 恢复程序**先选择 `retreat_empty(object='Bread')`，实际完成撤退，再把剩余对象顺序改为 Can、Cereal、Bread。它实际抓取并抬升 Can。独立离线物理 Trace 显示 Can 比初态升高 **0.17791 m**（`offline-physical-progress.json`）；这些真值没有进入在线 Agent/Belief。
4. Can 的目标放置在有限候选搜索中未找到可达位置。确定性层重复了 3 次无效放置搜索，之后升级模型。新恢复程序提出分段搬运，当前深度不足以许可首段；随后提案超出 0.15 m 局部规划范围被拒绝，未绕过保护。最终以 `recovery_request_budget` 退出，Can 没有放入目标，完整任务 reward 为 0。

这是“模型恢复 → 实际撤退 → 换对象 → 新抓取/抬升”的局部闭环证据，**不是 4/4 恢复成功，也不是开放横移规划成功**。实际脱离使用已有成熟 Skill，不能归功于新增图算法或新局部扫掠检查。

本轮软件问题也保留：计划状态文档不明确；精简反馈的 condition 字符串与 API 的 `{truth:...}` 不一致；模型 `.lower()`、保留变量名 `obs`、漏填 Skill 对象参数等导致程序被拒。最终统一了条件格式，明确返回枚举、保留名称与参数；缺失绑定返回结构化 REJECTED。仍可能出现模型协议错误。

受控空爪探针验证：已知闭爪前停止 + 新鲜开爪编码器允许**提出**运动，尚未获准运动。356 个新增扫掠样本只有 61 个明确自由、77 个没有有效深度，结果 REJECTED。没有据此取消释放/接触/路径门限。

### 实际工具成本与归因

| 运行 | SAM3 HTTP | GraspNet HTTP | IK HTTP | 新 LLM HTTP |

统计来自 HTTP 审计，不是 `perception_request` 事件数（事件包括缓存复用）。最终版推进到了 Can 抓持，不能直接把更高调用数判作更差效率；但重复不可达候选搜索产生了真实浪费，474 次 IK 尤其需要处理。当前接口没有把成熟 deposit 的完整可达性搜索独立暴露为可分支的预规划结果，这是下一步关键缺口。

恢复输入从第一版约 15076–17205 Token 降到第二版约 8508–8567；最终两次为 8938、9920。此为不同开发版本的实际账本读数，不是严格配对的单因素收益归因。所有新响应均 `finish_reason=stop`，没有输出预算截断；模型输出有大量 reasoning，但没有将其当作控制代码。

### 下一步判断

开放程序生成、共享 API、真实模型恢复和受控退出已可运行；Cereal 语义漏检补证获得了明确机制证据。**大规模评测 NO-GO；完整 4/4 验收未通过。** 下一步应优先将已有 deposit 的候选可达性/轨迹验证变成可查询、可参数化的预规划结果，并处理空爪/持物脱离的可验证自由空间，再比较放置质量策略是否影响后续接近路径。当前没有证明居中排序比原排序提高整段任务成功率。

仍需完善：主动观测的真实信息增益；可重组的低层抓取/释放阶段；目标质量差时的安全重操作；无效确定性 IK 搜索去重；持续物理下的安全保持。没有靠继续增加专用任务规则、放宽评分或换 Seed 获得成功。
