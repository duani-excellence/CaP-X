## 实现及公平边界

1. **共同底座**：新增有界精确输入缓存。SAM3 键包含 RGB 字节、查询、相机和标定，缓存结果深拷贝；不缓存异常。当前深度始终重新投影，每次验证始终获取当前公开观测，不跳过 final capture 或安全检查。
2. **同帧共享计算**：复用反投影、表面法向、候选/几何；区域缓存使用完整边界而非仅中心，避免同中心不同大小误复用。
3. **计划生命周期**：抓取计划只有在完整公开 RGB-D/机器人状态、运动版本、阶段及抓持/放置效果全部相同才复用；新来源 ID 本身不触发昂贵重算，物理变化必定失效。
4. **图的代价补证**：从未满足目标回归当前需求；合并共享 capture/语义特征的非瞬态条件，免费补齐未来条件；会随运动失效的 grasp/IK 计划不全部提前生成。TRUE 或同状态已耗尽条件保留。代价来自共同技能能力注册表的启发式时间尺度，不使用私有物理状态，不改变动作顺序或准入阈值。
5. **审计**：每次分割记录对象/查询、相机、Crop、图像/标定 hash、当前和原始来源、调用栈、实际或缓存结果；验证记录条件前后变化，计划记录实际命中，capture 记录采集与文件归档耗时。缓存命中、节点数或新 ID 均不等于真实信息增益。

G0/G1 都使用前 3 项及相同安全能力。G1 的额外差异为图回归、选择性范围与代价规划。V28 的 `no_graph_repair` 保留和 G1 相同的证据规划，仅关闭恢复范围授权；`no_selective` 使用保守后缀补证；`no_cost` 保留 V27 图策略以隔离新增代价规划。V27-G0/G1 通过开关关闭共同优化和 V28 代价策略，保留新审计字段；它们是当前文件中的 V27 策略对照，不是另一份旧仓库二进制。

未修改原物理评分、抓持/释放阈值、Sandbox 或父进程隔离。配置里只有策略版本/优化开关可跨对照不同；环境、预算和完整 Snapshot 的严格一致性检查保留。

## 决策归因与真实代价

- **共同优化**：Seed 0 正常配对中，未优化 V27 策略的 194 次 SAM3 降为 136 次（约 29.9%）；压力 V27-G1 的 228 次降为 G1-no_cost 的 136 次（40.4%）。使用 no_cost 隔离新增图代价策略。完全重复请求被缓存命中替代，当前几何、安全验证和物理动作保留。
- **代价规划独立增量**：压力 G1-no_cost → G1，GraspNet 4→2、IK 48→27、capture 34→33。图重新确认已完成目标，补当前所需条件，生成一个可用抓取计划后将 acquire-1 交给模型，暂缓另外两个会随运动失效的计划；实际没有计算这些无用计划。一个相同当前状态下的抓取计划在下一 Skill 派发时真正复用。
- **选择性补证**：压力 no_selective → G1，GraspNet 5→2、IK 53→27，但 capture 30→33，LLM 均为 2。G1 减少昂贵规划，仍多了轻量观测，不能描述为所有工具都下降。
- **图回归授权**：压力 no_graph_repair 与 G1 使用相同代价规划和 2/27 次 GraspNet/IK；关闭授权后 capture 35 对 33、LLM 4 对 2，仍没有额外物理进展。该单次配对显示无效续接请求减少，不能据此保证跨场景普遍节省。
- **不属于图的收益**：压力各优化组 SAM3 都为 136；没有证明图独有策略进一步减少 SAM3。精确缓存、点云共享是 G0/G1 共同底座。计划缓存键仍较保守，G0 的状态/效果更新顺序使该例没有命中，不能把所有 G0→G1 的计划差额都独立归功于图；no_cost 对照提供更清楚的调度增量。

## 安全表现、失败与限制

- Seed 0 正常/压力各组的 21 次物理动作及其前后真实状态完全相同；所有组均只完成同一个子目标。这提供本例中“没有靠提前失败或少做动作省调用”的直接证据。其他场景也按阶段和物理轨迹匹配分析，不能将 0/4 的低调用量当作高效率。
- 压力仅撤销证据，不移动物体。公开观测重验证成功后继续执行，未重做已完成搬运；这属于证据恢复，不能当作被碰倒物体的物理恢复成功。
- Seed 21 的明确原因是 `missing_bounded_wall_pair`，容器几何无法成立；Seed 7 是 `No current unambiguous instance for Cereal` 与 `Missing neighboring object geometry`。两场景均为 0/4，不能把低调用量计为成功操作的效率提升。Seed 7 的 G1/no_graph_repair 各 capture 5 次，G0/no_selective 各 2 次；SAM3 均 18、GraspNet 均 4、IK 均 0，图在这里没有调用收益，反而增加了采集开销。
- TCP 未收敛、当前容器/对象几何不足等共同能力瓶颈仍导致有界退出；源条件不能满足时没有通过改变阈值继续释放。详细 `last_error`、条件状态、Scope、actor 代码和结果均保留。
- 剩余大量 SAM3 调用来自不同物理帧、查询别名、双相机和 Crop。它们并非完全重复，当前没有足够反例证据证明可安全删去。下一步应单独验证深度刚体跟踪何时足以替代语义检查，以及可观测性变化/矛盾时的触发边界；本轮不跳过这些检查刷性能。
- 逐请求信息收益通过返回 mask hash、验证条件前后状态及后续实际物理进展追踪；条件变化不是信息熵估计，也不能只用新来源 ID 作为收益。重复 mask 没有带来新的语义几何，当前 capture 的时效性仍然需要保留。`final-aggregate.json` 保存实际语义/跨帧/计划复用及验证变化数量。
- 仍有优化空间：当前邻物几何缺失会阻止抓取，但部分 GraspNet 查询发生在该拒绝之前；该共同 Skill 顺序未在本轮改写。计划缓存也可能因保守的效果版本变化而失配。不能将剩余不同输入调用统称为必要，更不能宣称已达到最少工具调用。
- 代价模型是可解释启发式，并未证明全局最优；调度仍有 capture 开销。当前证据来自 PickPlace 开发场景，不能泛化为所有任务或正式成功率提升。
- SAM3/GraspNet 复用现有服务；旧 IK 端口不可用，使用项目原 CPU 求解器在系统分配的独立端口提供服务，所有比较共用该服务。宿主 NVML 有 driver/library mismatch，本轮沿用 Mesa EGL 和 CPU IK，未改驱动/依赖或停止其他项目服务。
